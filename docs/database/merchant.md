# Merchant Table

## Overview

The `merchant` table stores the core information for every Merchant registered on SamPay.

Each Merchant represents a legal entity that owns financial resources such as Wallets, Payments, Payouts, Refunds and Settlements.

Business rules related to Merchant lifecycle are documented in `docs/architecture/merchant.md`.

---

# Table Name

```text
merchant
```

---

# Columns

| Column | Type | Nullable | Default | Description |
|---------|------|----------|---------|-------------|
| id | UUID | No | gen_random_uuid() | Internal primary key |
| merchant_reference | VARCHAR(30) | No | - | Public merchant identifier |
| entity_type | merchant_entity_type | No | - | INDIVIDUAL / CORPORATE |
| legal_name | VARCHAR(255) | No | - | Registered legal name |
| notification_email | VARCHAR(255) | No | - | Business notification email |
| status | merchant_status | No | 'REGISTERED' | Merchant lifecycle status |
| kyc_status | merchant_kyc_status | No | 'PENDING' | KYC verification status |
| created_at | TIMESTAMPTZ | No | now() | Record creation timestamp |
| updated_at | TIMESTAMPTZ | No | now() | Record last updated timestamp |

---

# Primary Key

```sql
PRIMARY KEY (id)
```

---

# Unique Constraints


# Foreign Keys

None.

The Merchant table is the root entity for most business relationships.

# Indexes

No additional indexes are defined.

The following indexes are automatically created by PostgreSQL:

- Primary Key (`id`)
- Unique Constraint (`merchant_reference`)

Additional indexes should only be introduced when justified by production query patterns.

# Notes

- UUIDs are generated by PostgreSQL using `gen_random_uuid()`.
- All timestamps are stored as `TIMESTAMP WITH TIME ZONE`.
- Email addresses should be stored in lowercase.
- `merchant_reference` is immutable after creation.
- Merchant status transitions are enforced by the application layer.
- `entity_type` represents the legal type of the Merchant and is immutable after creation.
